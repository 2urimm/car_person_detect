# depth3d — RealSense 깊이 로그 3D 렌더링

`logs/depth_20261016_195111/` 같은 깊이 로그(`depth_*.npy` + `meta.json` + `index.csv`)를
`meta.json`의 카메라 내부 파라미터로 **실제 거리(m) 3D 점**으로 바꿔서 보여 준다.

- 거리: `meter = 값 × depth_scale_m(0.001)`, 0은 무효값이다. 65.535 m(포화값)를 포함해 15 m가 넘는 값은 뺀다.
- 좌표계: RealSense 규약을 따른다(X 오른쪽, Y 아래, Z 앞).
- 결과물은 `logs/depth3d_out/`에 저장된다. `logs/`는 `.gitignore`에 들어 있어서 git에 올라가지 않는다.

모든 명령은 `code/` 폴더에서 실행한다. 필요한 패키지는 numpy, scipy, opencv, matplotlib이다(추가 설치 없음).

## 1. 프레임 재생

### 브라우저 3D 뷰어 (마우스로 돌려 보기)

```bash
python -m http.server 8000
```

브라우저에서 <http://localhost:8000/depth3d/viewer.html> 을 연다.

- 원본 `.npy`를 직접 읽어서 브라우저 안에서 3D로 변환한다(데이터 복사 없음). 색은 바닥 기준 높이(0~3 m)다.
- **조작:**
  - 마우스: 왼쪽 드래그 회전, 휠 확대, 오른쪽 드래그 이동
  - Space: 재생/정지
  - ←/→: 1프레임 이동 (Shift를 같이 누르면 30프레임)
- **화면 위 옵션:**
  - **점 간격:** 몇 픽셀마다 점을 찍을지 정한다. 1이면 전체 해상도인데 그만큼 느리다.
  - **최대 거리:** 이 거리보다 먼 점은 그리지 않는다.
  - **월드 좌표:** 누적 지도에서 추정한 카메라 위치에 프레임을 놓는다. `poses.csv`가 있어야 한다.
  - **지도 겹치기:** 재생 중에 누적 지도를 함께 표시한다.
  - **누적 지도** 버튼: 지도 전체를 본다.
- **URL 옵션:**
  - `?frame=10000`: 시작 프레임
  - `?log=../logs/<로그폴더>`: 다른 로그 폴더
  - `?map=../logs/depth3d_out/<지도폴더>`: 다른 지도 폴더 (기본값은 루프 보정한 `full_v2_loop`)
- three.js는 CDN에서 받아오므로 인터넷 연결이 필요하다.

### mp4 영상

```bash
python depth3d/render_video.py --start 9000 --end 10500   # 1분 구간
python depth3d/render_video.py                            # 전체 (약 27분 영상, 1시간 안팎 소요)
```

- 카메라 뒤 3.5 m, 위 2.2 m에서 따라가며 보는 시점이다.
- 바닥에 1 m 격자와 2/4/6/8/10 m 거리 링을 그린다.
- 화면 왼쪽 위에 정면 최근접 장애물 거리(폭 ±0.5 m, 높이 0.15~2 m 범위)를, 오른쪽 위에 원본 깊이 영상을 표시한다.
- `--step 2`로 주면 2배속이 되고, `--stride 1`로 주면 전체 해상도로 그린다.

### 뷰어 표현 옵션
- **표현:** `면 (조명)`은 이웃 픽셀을 삼각형으로 잇고 조명을 줘서 실제 표면처럼 보인다. 시차 차이가 큰 물체 경계는 잇지 않는다. `점`은 예전처럼 점으로 그린다.
- **색:** `실사 톤`은 높이에 따라 바닥(회색) → 풀·덤불(초록) → 높은 물체(밝은 회색) 순으로 색을 근사한다. `높이`는 무지개(turbo) 색이다.
- **데이터:** 원본, 그리고 `logs/`에 있는 `<로그이름>_enhanced*` 보정본 폴더가 자동으로 목록에 뜬다. 바꿔도 보던 프레임 번호는 유지된다.

## 1-2. 깊이 보정본 (원본은 그대로, 새 폴더에 저장)

```bash
python depth3d/enhance.py --start 9000 --end 10500   # → logs/depth_20261016_195111_enhanced_009000_010499/
python depth3d/enhance.py                            # 전체 → logs/depth_20261016_195111_enhanced/ (약 32GB, 2시간 이상)
```

필터는 모두 **시차(disparity) 영역**에서 처리한다. 스테레오 깊이 오차는 거리²에 비례해 커지지만, 시차 오차는 거리와 상관없이 거의 일정하기 때문이다. RealSense 공식 후처리와 같은 방식이다.

1. **경계 튐 점 제거:** 앞뒤 물체 사이에 생기는 가짜 점을 뺀다. 기준은 3×3 범위의 시차 차이 1.5 px 이상이다.
2. **작은 구멍 채우기:** 넓이 300 px 이하인 구멍만 주변 값으로 채운다. 하늘처럼 큰 무효 영역은 그대로 둔다.
3. **경계 보존 평활화:** 시차에 bilateral 필터를 건다.
4. **시간 필터:** 직전 프레임과 시차가 비슷할수록 더 많이 섞어서 떨림을 줄인다. 연속 가중치를 써서 계단 무늬가 생기지 않는다.

출력 형식은 원본과 같다(uint16 mm `.npy` + `meta.json` + `index.csv`). 그래서 `--log` 옵션으로 다른 스크립트에 그대로 넣을 수 있다.
한계: 먼 배경의 큰 물결 무늬는 스테레오 매칭이 원래 만드는 덩어리 오차라 한 프레임 필터로는 남는다. 아래 TSDF 메시에서 여러 프레임을 평균하면서 줄어든다.

## 2-2. TSDF 표면 메시 (가장 "실제처럼" 보이는 결과)

```bash
python depth3d/build_mesh.py --start 9000 --end 10500 --log logs/depth_20261016_195111_enhanced_009000_010499
```

- `build_map.py`가 만든 `poses.csv`(기본 `logs/depth3d_out/full`)로 프레임들을 같은 공간에 겹친다. 그다음 복셀마다 "표면까지의 부호 거리"를 가중 평균한다(TSDF). 이렇게 하면 프레임마다 다른 노이즈는 평균되어 사라지고, 구멍은 다른 프레임에서 본 것으로 메워진다.
- 평균된 표면을 Surface Nets 방식으로 삼각형 메시로 바꾼다. numpy만 쓰고 추가 설치는 없다.
- 기본값:
  - 5 cm 복셀
  - 표면 앞뒤 ±15 cm 범위만 계산
  - 6 m까지의 관측만 사용 (먼 관측은 거리²에 반비례하게 가중치를 낮춤)
  - 3프레임 이상에서 관측된 복셀만 남김
- 출력은 `logs/depth3d_out/mesh_<시작>_<끝>/`에 생긴다: `map_mesh.ply`(정점 색 포함), `poses.csv`, `level.json`, `mesh_preview.png`(전체 모습 + 길 위 시점).
- 뷰어에서 볼 때: `viewer.html?map=../logs/depth3d_out/mesh_009000_010497` → **누적 지도** 버튼을 누르거나 재생 중에 **지도 겹치기**를 켠다.
- 전체 경로에 쓸 때는 `--keyframes --voxel 0.08`을 권장한다(메모리와 시간 절약).
- 한계: 포즈 추정이 틀린 구간(`degenerate`)에서는 표면이 겹치거나 판처럼 튀어나온 면이 생길 수 있다.

## 2. 누적 3D 지도

```bash
python depth3d/build_map.py                               # 전체 로그 (1시간 안팎)
python depth3d/build_map.py --start 9000 --end 10500      # 일부 구간
```

출력은 `logs/depth3d_out/<이름>/`에 생긴다. 이름 기본값은 `map_<시작>_<끝>`이고 `--name`으로 바꿀 수 있다.

| 파일 | 내용 |
|---|---|
| `map.ply` | 5 cm 복셀 누적 점구름. 높이에 따라 색이 들어가 있고, CloudCompare나 MeshLab에서 열 수 있다 |
| `map_light.ply` | 10 cm로 줄인 버전. 브라우저 뷰어가 이 파일을 쓴다 |
| `poses.csv` | 프레임별 카메라 자세. world←camera 4×4 행렬의 앞 3행이고, ICP 품질(fitness, rmse, degenerate)과 키프레임 여부가 같이 들어 있다 |
| `level.json` | 바닥 기준 기울기 보정 회전과 카메라 높이 |
| `map_top.png`, `map_persp.png` | 미리보기 이미지 |

### 방식과 한계

- 로그에는 카메라 위치나 IMU 기록이 없다. 그래서 **연속 프레임의 형상만 맞춰서(point-to-plane ICP)** 카메라가 어떻게 움직였는지 추정한다.
- 카메라가 차체에 고정되어 있다고 보고, 바닥 위 평면 운동(전후, 좌우, 세로축 회전의 3자유도)만 추정한다.
  - 장점: 높이와 기울기는 드리프트가 생기지 않는다.
  - 단점: 실제로 경사로나 언덕을 오르내리면 지도에서 그 부분이 휘어 보인다.
- **긴 경로일수록 위치 오차가 쌓인다.** 루프 클로저(같은 장소 재방문 보정)는 없다.
- 바닥만 보이거나 형상 특징이 적은 구간은 정합이 불안정하다(`poses.csv`의 `degenerate=1`). 이런 구간에서는 먼저 "멈춰 있음"을 초기값으로 다시 맞춰 본다. 그래도 실패하면 회전은 멈추고 이동만 서서히 줄이면서 위치를 이어 간다.
  - 예전 버전(`full`)은 직전 속도를 그대로 유지했다. 그래서 제자리 회전 직후나 정지 중에 몇 초 만에 수백~수천 도를 도는 가짜 회전이 쌓였고, 끝점이 시작점과 442 m나 어긋났다. 현재 버전 결과는 `full_v2`다.

## 3. 루프 클로저 (출발 위치 = 도착 위치)

```bash
python depth3d/loop_close.py                      # 끝 프레임 ↔ 로그 처음 3분 중 가장 잘 맞는 프레임을 자동으로 찾음
python depth3d/loop_close.py --pair 41685:2088    # 직접 지정 (끝프레임:시작프레임)
python depth3d/loop_close.py --pair 41685:2088 --laps 1   # 반시계로 한 바퀴 (이 로그의 실제 경로, 결과: full_v2_loop)
```

`--laps`는 위에서 봤을 때 몇 바퀴 돌았는지를 뜻한다(+1이면 반시계 한 바퀴, -1이면 시계 한 바퀴).
- 깊이만으로 추정한 방향은 오차가 크게 쌓인다. 이 로그는 끝에서 약 180° 어긋났다. 그러면 "시작=끝" 조건만으로는 경로를 어느 쪽으로 감아야 할지 정할 수 없어서 경로가 꼬인다.
- 실제 경로가 반시계 한 바퀴였다는 정보를 주면 전체 회전량이 −381°(= 한 바퀴 + 끝 방향 −21°)로 고정되고, 경로가 닫힌 고리 모양으로 풀린다.
- 방향 보정은 주로 ICP가 실패한 구간에 몰린다. 이 로그에서는 엘리베이터 구간(약 406~558초, 사방이 가까운 벽인 장면) 직후인 510~570초에 가장 많이 들어갔다.
- 엘리베이터로 층이 바뀌었어도 높이 변화는 깊이로 잴 수 없다. 지도에서는 모든 층이 같은 높이에 겹쳐 그려진다.

이 로그는 출발한 곳으로 돌아와서 끝난다. 그 사실을 이용해 누적 오차를 바로잡는다.

1. 마지막 프레임을 초반 프레임들과 ICP로 맞춘다. 이렇게 해서 "끝 카메라가 시작 카메라 기준으로 어디에 있는지"를 직접 잰다. 같은 난간과 기둥이 보이는 장면끼리 맞는다.
2. 모든 프레임 자세를 노드로, 연속 프레임 ICP 결과를 간선으로 하는 2D 포즈 그래프(x, z, 방향)를 만든다. 여기에 1번 측정을 루프 간선으로 추가해 푼다. 방향을 먼저, 위치를 나중에 푸는 두 단계 선형 최소제곱이라 반복 계산 없이 바로 풀린다.
   - 오차는 경로 전체에 나뉜다.
   - 정합이 실패했던 구간(`degenerate`), 많이 움직이거나 많이 돈 구간에 더 많이 나뉜다.
   - 멈춰 있던 구간은 거의 건드리지 않는다.
3. 바로잡은 자세로 누적 지도를 다시 만든다.

- 출력: `logs/depth3d_out/<지도>_loop/`
  - `poses.csv`, `map.ply`, `map_light.ply`, `level.json`, 미리보기 이미지
  - `loop_compare.png`: 보정 전후 경로 비교
  - `loop.json`: 루프 측정값, 보정 전후 시작-끝 간격
- 원본 지도 폴더는 그대로 둔다.
- 한계:
  - 루프 제약이 하나뿐이다. 그래서 시작과 끝이 맞는다는 것만 보장되고, 중간 구간의 모양은 오차를 어디에 나눴느냐에 따라 달라진다.
  - 경로 중간에 같은 장소를 다시 지나간 곳이 있으면, 그런 곳을 추가로 맞춰야 더 정확해진다.
